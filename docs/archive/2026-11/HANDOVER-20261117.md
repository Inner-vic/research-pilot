# 交接检查与首次使用

更新：2026-11-17。**可以交接当前ResearchPilot代码、完整Skill及已验证的研究工作链。** 同事可以用下面的路径，在自己的模型项目准备环境并通过对话使用；本人账号、项目事实和远端资源仍须现场核对。此处“可交接”不表示任意模型、平台或评价方式已全部验收。

## 同事按这条路径开始

1. 用本人GitLab账号打开仓库并克隆main。Python需3.11以上；安装并登录Codex，准备组织允许的软件包访问条件。
2. 在克隆的ResearchPilot框架仓库执行下面的命令。目标路径应是同事自己的现有模型项目；不要把框架仓库当成模型目录。

```powershell
git clone https://github.com/Inner-vic/research-pilot.git
cd research-pilot
python scripts/setup.py --project-root "D:\Projects\MyModel"
```

把示例路径改为实际模型项目绝对路径。安装会准备完整用户Skill、该项目的独立Python/官方Codex SDK和本地工作台。安装本身模型调用0次、平台写入0次、研究未启动；无实验的引导页是正常状态。用户Skill可被多个项目复用，换项目仍需初始化其本机环境。

3. 用Codex打开刚才指定的模型项目，明确选择ResearchPilot并发送下述消息，也可写`$researchpilot`。若新入口未显示，先重新打开项目，仍不显示时重启Codex。

> 使用 $researchpilot，先检查当前项目，说明已有代码、数据、基线、训练和评价入口。先不要提交训练；已经能读取的信息不用重复问，缺少的信息集中列出。

4. 让Codex根据当前项目整理接入。本人需要说明或确认：无法查到的数据访问权限与划分、主要指标及方向/目标、可改范围、所选平台资源及停止条件。用户不必手写内部JSON或复制作者配置。
5. 完成本人执行接入的只读核验。选择LPAI时另需组织官方LPAI Skill/SDK及本人认证、namespace、队列、组件和挂载；选择项目命令方式时需提供现有远端任务系统实际可用的固定驱动。不要为了通过准备检查临时切换平台。本人Codex账号也要能够访问研究主会话与评审所选模型。
6. Codex说明具体方案、资源和停止范围后，再明确授权。首次可选择本人独立CPU检查任务；它只核验提交、原任务编号、输出、日志和停止行为，不代替模型质量验收。普通研究沿同一SDM 13步和原门禁执行。

阶段就绪条件、安装输出和排障见[安装与触发说明](../../delivery/INSTALLATION-MODES.md)。只有Skill安装完成时，不应勾选“本人平台和项目已经可以训练”。

## 本人配置和责任交接

接手人需本人登录确认仓库可读；维护代码还需对应写入权限。现有组成员权限记录不等于已经核实这位接手人，发送仓库链接也不等于移交组Owner。组管理责任、后续维护人与历史原始证据保管人需要交接双方明确；本次不新增成员或修改角色。
