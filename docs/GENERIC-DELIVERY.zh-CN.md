# 项目接入指南

ResearchPilot 在当前模型项目中工作。接入的目标是让系统准确识别数据、训练与评价入口，并通过确定的执行接口完成实验。研究方案、评审、预算和结果接续由统一研究流程管理。

使用者可以先在 Codex 中提出任务，由系统调查已有材料并整理配置；项目维护者负责提供无法从代码取得的业务语义、访问权限和执行接口。

## 接入内容

| 部分 | 项目需要提供的内容 |
| --- | --- |
| 数据与评价约定 | 数据版本、训练/验证划分、标签或连续目标的含义、评价程序与主指标 |
| 训练与实现 | 模型代码、起始配置或权重、训练入口、允许修改的文件及受保护文件 |
| 功能检查 | 适用检查项、实际检查程序、可验证的检查报告 |
| 远端执行 | 执行平台、环境依赖、提交与查询接口、数据读取和产物回收方式 |
| 研究范围 | 目标、资源预算、任务或时间上限、失败处理约定与停止条件 |

数据和评价约定应允许后续实验进行可靠比较。改变数据划分、评价程序或检查点选择规则时，需要明确其对已有结果可比性的影响。

## 项目发现与配置

入口会读取当前项目的说明、源码、训练配置、已有结果和研究索引。存在 `researchpilot.project.json` 时，核对其中声明的文件与摘要；没有描述文件时，先调查项目，再整理接入事实。

| 文件 | 职责 |
| --- | --- |
| `researchpilot.project.json` | 可移植的项目事实：源文件、数据与评价约定、训练和功能检查入口、可改范围 |
| `.bmad-ml/ENVIRONMENT.json` | 当前项目使用的 Python、SDK 和 Skill 安装信息 |
| `.bmad-ml/CAPABILITIES.json` | 当前环境具备的执行工具、资源及平台配置 |
| `.bmad-ml/CURRENT.json` 等研究索引 | 已登记研究及其配置位置，用于定位已有研究 |

项目描述可随源码维护；账号、凭据和本机配置应在使用者环境中独立准备。实际描述字段与程序入口见[项目接入技术参考](../skills/sdm-module/sdm-lifecycle/references/project-integration.md)。

## 远端执行方式

**官方 LPAI 组件**使用已配置的官方能力提交和查询任务。需要明确组件、队列、资源、输入数据和输出位置，并核对当前账号的实际权限。

**项目命令驱动**用于对接项目已有的远端任务系统。固定驱动文件实现以下操作：

| 操作 | 约定 |
| --- | --- |
| `probe` | 核对执行环境及所需能力 |
| `submit` | 提交绑定确切配置的任务，返回可追踪身份 |
| `lookup` | 按原请求查询任务是否已创建，处理提交响应未知的情况 |
| `read` | 读取同一任务的实际运行状态 |
| `collect` | 回收所属任务的产物及验证所需信息 |

驱动承担具体平台操作，研究控制器管理授权、预算、唯一请求和接续。提供接口不代表任意平台已经可用，新平台仍需部署并验证其实际行为。`local-engineering` 仅用于非机器学习工程检查，训练与评价在已授权远端环境执行。

## 评价与功能检查

当前通用结果接入支持以下规定格式：

| 任务 | 主要指标 | 核验依据 |
| --- | --- | --- |
| 多类别分类 | 准确率、宏平均 F1、均值 IoU | 固定划分、逐样本标签与预测、类别语义和混淆计数 |
| 标量回归 | MAE、MSE | 固定划分、逐样本目标与预测、单位及目标语义 |

指标及其优化方向由项目声明。检查点选择支持最后一轮，或主要指标最优且并列时选择最早检查点。完整产物格式以[技术参考](../skills/sdm-module/sdm-lifecycle/references/project-integration.md)为准。

分类均值 IoU 基于逐样本类别计数，不能作为图像分割或 RoadModel Pillar 评价的接入证明。其他结果形态、指标或选择规则需要补充适配和验证。

功能检查由项目给出适用项及实际程序，例如输入输出检查、微型训练、保存与恢复一致性。远端执行和结果回放使用相同检查要求。功能预检所需环境及计算消耗应包含在执行范围中。

## 接入验证

建议按以下顺序确认项目可投入研究：

1. **只读发现**：能够定位源文件、数据与划分、训练和评价入口，明确尚缺的事实。
2. **执行准备**：本人环境和资源可用，功能检查及产物格式能够核验，研究范围已确认。
3. **独立实验**：在授权范围内提交任务，准确追踪排队和运行，回收并验证完整结果。
4. **持续接续**：首轮真实结果进入分析与评审，实际变更经检查后提交后继，最终按约定停止。

前三项可支持单次执行；持续研究还需验证结果到后继的完整接续。软件检查、账号连通、真实执行和研究结论分别记录，当前产品范围见[支持范围](EXECUTION.md)。

## 兼容与升级

研究开始后固定其运行代码、配置与关键依据。新版本用于新建研究；已有研究通过原记录核对与恢复，不因升级 Skill 而就地改写版本、任务身份或预算。

接入过程中遇到未支持的评价、产物不完整或提交结果未知，应保留原记录并说明缺口。运行状态的处理见[排障指南](CONTINUOUS-RUNTIME.zh-CN.md)。
