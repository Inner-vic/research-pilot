# 运行状态与排障

持续研究由后台研究控制器推进，工作台展示已登记研究的实际状态。排查时先确认任务范围、当前阶段和具体原因，再核对所属任务与记录。

## 判断结果分析后的状态

先区分本次任务是单次评测还是持续研究。单次评测交付分析后正常结束；持续研究需进一步查看是否已启动、是否进入结果驱动接续，以及当前能否自动推进。

“后台进程存在”“研究线程就绪”“分析已完成”和“下一任务已提交”分别表达不同事实。工作台能打开，也不代表研究控制器正在工作。各状态含义见[任务范围与接续状态](TASK-SCOPE.zh-CN.md)。

## 常见情况

| 现象或状态 | 核对重点 | 处理路径 |
| --- | --- | --- |
| 训练长时间排队或运行 | 原平台任务编号、实际状态和最近观察信息 | 继续观察同一任务，区分排队与完成后接续 |
| 结果已返回，分析尚未完成 | 结果产物是否齐全，是否已派发分析及调用是否结束 | 按回收、核验或模型调用的实际阶段处理 |
| 分析完成但未进入持续研究 | 单次范围、持续目标与授权、接入和控制器状态 | 按具体前置原因补齐，单次任务无需补启动 |
| 方案或代码评审受阻 | 逐轮意见、待补证据与修订回应 | 解决原异议后重新核验相关对象 |
| 后台离线 | 所属控制器、配置和原任务回执 | 先核对已有任务，再沿原研究恢复入口接续 |
| 研究暂停或预算耗尽 | 原暂停决定、剩余范围及停止原因 | 暂停需明确继续；新增范围或预算需重新确认 |
| 提交响应未知 | 原请求键、平台身份及完整查询结果 | 查询并对账原请求，避免改名重提 |
| 证据或关联待核实 | 文件完整性、项目路径及入口关联冲突 | 保留现场，核对并修复原记录后重新读取 |

## 工作台没有显示平台任务

工作台显示当前项目已登记的研究，不是整个平台账号的任务总览。核对页面中的项目目录、研究编号和登记配置。属于其他项目的任务应在对应项目中查看。

同一个研究恢复时沿用原任务身份。名称前缀相似不能证明重复提交，判断应使用研究、请求及平台任务记录。

## 暂停与恢复

暂停阻止新的分析、方案和训练派发，已提交的远端任务需要单独管理。恢复时核对已有任务、完成回执、所属版本及授权范围；结果未知的调用先对账。

已固定研究版本与新安装包不同，是需要明确的版本状态。安装更新不会自动恢复研究，修复也不应通过改写历史回执或放宽原检查条件完成。

## 提供排障信息

说明项目与研究名称、任务范围、当前阶段、具体提示和相关任务编号。通过项目记录保留必要的配置版本、日志与回执。分享时排除访问令牌、密钥和不相关项目材料。

能力边界见[支持范围](EXECUTION.md)，执行链路见[系统架构](ARCHITECTURE.md)。
