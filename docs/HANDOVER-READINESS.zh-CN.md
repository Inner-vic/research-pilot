# 首次使用核对

本页用于新用户、新设备或新模型项目投入使用前的准备。安装操作以[安装说明](delivery/INSTALLATION-MODES.md)为准，项目接口以[接入指南](GENERIC-DELIVERY.zh-CN.md)为准。

## 准备完成的标志

| 范围 | 应核对的事项 |
| --- | --- |
| 本机环境 | Codex 可用，完整 ResearchPilot Skill 可被发现，项目使用正确的 Python 与 SDK |
| 模型项目 | 当前目录正确，能够找到训练、功能检查和评价入口 |
| 数据与结果 | 数据和划分身份明确，权重及已有结果来源可核对，评价口径一致 |
| 执行环境 | 本人平台身份、资源、数据读取和输出位置可用 |
| 任务范围 | 明确单次评测或持续研究，并确认目标、修改范围、预算及停止条件 |
| 工作台 | 页面中的项目和研究正确，能够查看状态、详细记录与报告入口 |

安装成功、账号可访问、项目接入完成和持续研究经过验收是不同阶段。已有案例可以帮助理解操作，不能代替当前环境的核对。

## 首次研究建议

先让 ResearchPilot 只读调查当前项目，核对缺项后再提出具体方案。选择能够代表实际项目、且成本受控的独立任务验证提交、观察、回收和结果核验。

需要验证持续研究时，还应观察首轮结果如何进入分析，后继方案依据、实际代码修改、独立评审及下一任务是否完整关联，最终是否按约定停止。单次任务成功不能单独证明整个持续链已经可用。

记录实际提示词、确认方案、任务与结果、评审和停止原因。验证出现问题时沿原记录处理，不通过增加预算或改写条件追认成功。

## 环境与责任

使用本人账号和项目配置，不复制他人的凭据、运行环境、研究目录或已消费授权。团队应明确源码维护者、平台接入维护者、数据与评价负责人，以及研究结果的保管位置。

当前支持能力及尚待验证的场景见[支持范围](EXECUTION.md)。已完成案例与历史交接记录见[参考资料](archive/README.md)。
