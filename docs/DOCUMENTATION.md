# 文档维护规范

产品文档描述当前行为，帮助读者理解、使用和接入 ResearchPilot。开发过程、验收原件与设计讨论有独立保存位置，不按工作发生顺序追加到产品页面。

## 文档分工

| 文档 | 应包含 | 不包含 |
| --- | --- | --- |
| README | 定位、核心能力、快速开始、必要边界与导航 | 修复过程、测试数量、任务编号和逐次交付声明 |
| 使用与安装指南 | 操作、输入、预期结果和常见问题 | 内部调用链、逐节点协议字段和作者本机配置 |
| 项目接入与技术参考 | 接口、环境、产物约定和适用条件 | 将接口存在写成所有平台已验收 |
| 支持范围 | 当前能力、验证覆盖、已知限制和后续验证重点 | 日期倒序的实现日志 |
| 架构与流程 | 组件职责、依赖、数据流和执行约束 | 每次修改经过和重复的验收汇报 |
| 版本变更 | 用户可感知的行为、修复、兼容性及升级影响 | 完整工具输出或会话转录 |
| 参考与归档 | 实验事实、验证范围、证据摘要和历史设计 | 未标明范围的当前能力承诺 |

## 内容更新

行为改变时，直接修订所属章节，并删除被替代的说法；同一事实由一份主文档负责，其他页面引用它。不要在每份文档开头复制相同交付段落。

首页以产品和使用路径组织，主要导航不要求先阅读验收报告或内部规范。版本号、日期、测试数和平台任务编号仅在对应版本或证据材料中使用。

方案、实验、评审及状态名称采用[术语表](TERMINOLOGY.zh-CN.md)，图文使用相同名称。具体限制集中到[支持范围](EXECUTION.md)，对操作有直接影响的条件在相关步骤中就近说明。

## 事实与记录

依据已发布代码和可核验记录描述能力。明确区分产品要求、已实现接口、软件检查、真实执行和研究结论。示例提示词标明示例性质，不将示例目标或资源写成默认配置。

真实实验与机器核验原件保持其版本和事实。历史文档归档后明确标注状态，修正相对链接并提供索引；不要改写旧结果来符合新产品叙述。开发者本机的路径、凭据和未发布研究记录不进入分发文档。

## 发布核对

检查主要阅读路径、命令与参数、状态和图文名称、相对链接与章节锚点。重组历史材料时确认来源及链接仍可追溯。文档变更只提交相关文件，不混入运行配置、研究数据或无关源码修改。
