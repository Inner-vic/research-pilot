# ResearchPilot · 持续研究工作台

Codex + SDM 的持续机器学习研究工具。用户在 Codex 中确认初始方案后，后台按任务结果分析、审议、实施并提交下一实验；本地工作台展示研究主线、实验指标和方案脉络。

## 先看一个真实案例

[指骨轮廓分类：14次实验的完整示例](examples/distal-outline/README.md)，包含初始方案、失败分支、历史最优保留及达到目标的过程；验证 macro-F1 从0.8450到0.9155。[一步步使用引导](examples/distal-outline/RUN-GUIDE.zh-CN.md)从 `/ ResearchPilot` 开始，区分只读案例和使用你自己的LPAI开展新研究。

## 项目来源与命名

ResearchPilot 基于原 BMAD ML / SDM 演进，重点补充真实平台执行、结果驱动的持续研究、模型协作、暂停恢复与可视化工作台。继承的治理协议、证据规则和组件归属继续保留。

[查看与原 BMAD ML 的完整对比](docs/COMPARISON-WITH-BMAD-ML.zh-CN.md)。对比基线为维护者保留的 2026-09-18 初始模板，不代表原项目后续版本。

仓库已更名为 `research-pilot`；界面和 Skill 显示名统一为 **ResearchPilot**；兼容调用名仍为 `bmad-ml`。现有安装与研究目录可继续使用。

## 快速开始

前提：安装并登录 Codex 客户端，电脑有 Python 3.11+，能访问批准的软件包源和 LPAI。无需本地 GPU、PyTorch、Node 或额外前端构建。

```sh
git clone https://github.com/Inner-vic/research-pilot.git
cd research-pilot
```

在 Codex 中打开这个目录，输入 `/`，选择 **ResearchPilot** 并发送默认引导。项目内已提供可发现的 Skill 入口：首次会自动准备独立 Python 环境、官方 Codex SDK 和工作台，再引导你说明研究任务。不会自动训练或另开前台聊天。

也可一次性安装为所有项目可用的用户 Skill：

```sh
python scripts/setup.py
```

初始化自动完成：构建/校验一个自包含 Skill、备份升级、安装固定版本官方 Codex SDK（复用既有 Codex 登录）、保存本机运行路径、启动/复用当前项目的工作台并输出访问链接。重复执行不创建第二个研究后台或重复训练。端口 8792 被其他程序占用时自动改用空闲端口。

**仍需你配置：官方 LPAI Skill、官方 SDK/正常平台认证，以及自己的 namespace/组件/数据和资源范围。** 不使用作者的账号、Token、任务或运行目录。ResearchPilot 会根据你的环境引导补齐；已有 Codex 登录失效时也需本人正常登录。

## 怎么用

直接说：“帮我研究这个模型，数据在……，希望……”。它先检查项目，逐步询问缺失的任务、基线、主指标和执行范围。确认方案后才开始远端训练；后续按目标持续迭代，不按预设轮数结束。

- 概览：主指标、当前最优、最新结果与执行状态。
- 实验记录：参数、训练曲线、可展开的类别 P/R/F1、混淆矩阵与原始证据。
- 研究主线：最新方案/实验及其实际选用的上游基线。
- 研究脉络：默认只显示方案和结果；点击方案节点自动展开本方案及真实下游分支的过程，再点收起；切换方案自动收起上一分支。没有全局“完整过程”模式，不把较差结果擅自标记为否定或搁置。
- 暂停/继续：网页委托原 SDM 协调器，保留原研究/Context/任务/Guard；未知请求先对账，不重复提交。

工作台绑定 **当前工作目录 + 研究编号 + 当前配置**，读取同一份实验记录。首次确认并登记研究后会自动显示；加载 Skill 本身不建研究。当前 Codex 聊天全文不会同步到页面，后台实施线程与前台聊天有明确区分。

## 能力与边界

已有官方 LPAI SDK 真实连续研究记录、结果驱动审议与实施、原身份恢复以及网页暂停/继续。未知平台写入和模型调用优先对账，工程修复不能冒称全程自主。

当前公开数据标准生产器/核验器是固定验证协议的二分类，主目标为 macro-F1。类别报表可展示多类混淆计数，但完整多类/分割、IoU 评估器和对应候选规则仍需按真实任务适配验收。项目启动不会自动授予训练权限。后台需电脑和网络在线，默认不创建定时消息或开机研究任务。

## 开发

`skills/bmad-ml/` 是用户入口，`skills/sdm-module/sdm-lifecycle/` 是 SDM 核心；`scripts/` 是安装和维护工具。工作台复用现有记录，不拥有第二套实验引擎。图组件已构建并含许可声明，无 CDN。

`.runtime/`、`.bmad-ml/`、`.research/`、`.maintenance/`、凭据、数据、权重和个人运行证据不进入仓库。升级只影响新研究；运行中的冻结版本不就地改写。标准 GitLab CI 只运行代码/控制与报表检查，不调用模型或 LPAI。

公开副本的来源、示例配置与验证范围见 [发布说明](PUBLICATION.md)。
