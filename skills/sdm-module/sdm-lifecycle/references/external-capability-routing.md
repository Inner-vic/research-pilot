# 外部能力执行优先级

本规则适用于全部外部能力，包括资源平台、GitLab、CI、存储和评审服务。
每个外部操作的执行入口、项目驱动与平台交接均遵循同一顺序：

1. 恢复目标、对象身份、账号范围和已有授权。读取所绑定平台 Skill 与当前
   官方 SDK/CLI 文档或帮助，核查当前操作和字段，不因其他操作受支持而推断
   本操作存在。已有有效能力检查可复用，不每轮重做全量发现。
2. 优先调用官方 SDK/CLI 的受支持操作。记录接口/版本来源、观察时间、支持
   字段和缺失能力；只读发现不得产生新任务或收费资源。
3. 无对应接口、缺少必要字段或明确不支持时，定向转入正常浏览器界面；浏览器
   控制无法操作时使用 Computer Use。仅补齐缺口，不重复查询已获取事实。
4. 官方 SDK/CLI 与界面均无法满足时，评估自研适配器。自研必须基于受支持的
   接口或明确的公开集成合同，定义输入输出、版本、对象身份、失败与重复请求
   处理、执行后读回和必要验证。不得编造私有接口、绕过权限或平台强制审批。
   缺少依据时报告具体能力缺口，不能声称已接通。
5. 路由变化不产生新授权。资源申请须先自动完成可用性调查，给出完整配置、
   全角色实例/卡数、报价与预算、期限、停止策略和推荐理由，经用户确认具体
   方案才启动；GitLab 等写操作遵循其任务范围和已有授权，不统一追加资源审批。

资源草稿由 `resource_planning.discovery_route` 输出下一采集路径；其他平台
交接可通过统一协调器的`external_operation`驱动执行探测和写后核验，见
[外部操作执行合同](external-operations.md)。内置LPAI官方SDK映射不代表已接通
所有平台；浏览器/Computer Use仍需项目适配并遵守交互授权。审批、认证和
写入错误不属于能力缺失，不能自动换路径再写。

只读验收也必须保留查询作用域：资产目录、队列清单和任务状态不是同一种事实。
官方资产接口返回空列表，不能推断平台没有数据、没有GPU或不存在其他接口可见的对象。
精确查询未找到后，可在同namespace按受支持的分页/筛选做有界定位；区分资产本体、
版本名与挂载名，不把未知标识补成确定的UID。保留成功、未找到、认证/权限及网络错误，
失败不能规范化为成功空列表。单页查询不声明完整枚举；CLI连通不等于资源可用性已验收。
通过统一execute进行有限只读验收时，应记录实际派发次数、原始回执摘要和恢复是否重派，
且不得由此推导34节点训练、平台写操作或GPU能力均已验证。

GitLab/Jenkins 普通任务已有内置适配器，见[SCM/CI 接线](scm-ci.md)；仍须核验当前账号、项目和真实结果，不以操作目录占位代替接通。
