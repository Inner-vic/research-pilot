# 当前项目接入同一条13步流程

ResearchPilot不以项目名、模型框架、LPAI组件编号或宏平均F1作为研究身份。
先读取当前项目，再准备实际输入和执行范围。项目接入提供事实与具体操作，
原SDM契约、同一个研究控制器、双会话审议、提交检查、预算与科学裁决继续负责推进。

## 入口与配置从哪里来

Skill的`researchpilot.py inspect --project-root 当前目录`自动读取
`researchpilot.project.json`（存在时）、已有源码/配置/研究索引，和项目本地
`.bmad-ml/CAPABILITIES.json`、`.bmad-ml/ENVIRONMENT.json`。没有项目描述时，
先检查已有训练脚本、数据约定、评价程序与结果，内部整理出项目事实。
只询问无法查到的数据权限、评价目标、资源与停止范围；不让用户填写内部JSON。

`researchpilot.project.json`描述项目自有的输入、输出、训练/功能检查/评价入口，
可改文件、受保护文件、固定数据划分、评价方法，以及原SDM契约内容。
可用`research_project.freeze`固定已核实文件；初始化以`workload.adapter=project/v1`
和该快照引用接入原`research_initialize.py`，不启动另一条研究循环。

账号、SDK、队列、组件或其他执行器配置留在当前项目/接手环境，不写入可分发Skill。
执行能力描述只说明工具和资源，不能代替研究目标、实验结果或用户授权。
已有研究继续沿原配置和冻结运行，不因打开另一个聊天而迁移或恢复。

## 三类接入各负责什么

| 接入 | 实际职责 | 仍由共同流程负责 |
| --- | --- | --- |
| 项目 | 源文件、数据/划分、可改范围，既有训练与功能检查入口 | 步骤1—8的原契约、基线、计划、独立审议与确切版本检查 |
| 执行 | 探测环境、提交、原请求查询、按编号读取状态和回收产物 | 步骤9—10的授权、Run/Attempt登记、原Guard、唯一请求、预算、等待和恢复 |
| 评价 | 受保护评价程序、逐样本输出、主要指标与优化方向 | 步骤11—13的身份核验、指标重算、完整证据、独立审查和原科学裁决 |

执行接入支持已有官方LPAI组件方式，以及项目提供的命令驱动方式。
命令驱动仅实现`probe/submit/lookup/read/collect`五个操作，命令与驱动源码需固定摘要。
它可以接入项目已有的远端任务系统；不会因此自动获得账号或执行权限。
二者共用原Manager的写入事务和Guard；命令方式与组件方式共用原事件源的
持久观察、退避与结果交接。结果未知时只按原请求查询，禁止重新提交。
`local-engineering`方式仅用于非机器学习工程检查，拒绝本地训练请求。

项目训练和评价程序在已授权远端环境执行。核心不要求PyTorch工厂函数、
二分类张量、固定模型源文件名或特定优化器。项目声明哪些文件可改，
其余检查、评价程序、数据及划分受保护。每次改动仍须受审并绑定实际提交字节。

## 评价与功能检查

当前独立重算接入包括多类别分类准确率、宏平均F1、均值IoU，及标量回归MAE/MSE。
其中分类均值IoU由逐样本混淆计数计算，不代表RoadModel分割或Pillar评价已经接通。
指标名称、越大/越小越好的方向、目标和检查点选择方式来自项目。
选择规则支持最后一轮或主要指标最优且保留最早并列者。
其他指标、选择规则或结果形式明确报告接入缺口，不套用二分类分数或猜测通过。

功能预检由项目给出适用项和实际检查程序。受保护远端入口执行检查，
回收与回放调用同一个`project_preflight.verify_report`，拒绝缺项、缺证据或
把适用检查改成“不适用”。既有二分类微型拟合与精确接续检查保持原要求。

G07仍承担原SDM的标签语义职责，并仍进入G02的原引用闭包。
离散类别沿用原校验；连续目标显式声明名称、单位、范围和对应语义，
不能伪造类别或混用两种表示。相关原owner schema、目录摘要和语义校验器一起演进；
旧冻结的规范文件和目录摘要保持原样。

## 启动和结果驱动后继

沿原初始化、首轮方案/代码审议、共同提交门禁和冻结监督器启动。
初始化只准备配置，返回 `automatic_iteration_active=false`。Codex在已有研究授权范围内，
使用初始化返回的冻结 `research_launch.py`，传入 `--config` 和 `--project-root`。
该入口登记当前项目、启动唯一的原监督器，并核对实时身份和研究控制线程。
只有返回 `automatic_iteration_active=true`，才可向用户报告后台自主迭代已启动。
`--inspect`只核验，不启动研究。若已有启动记录却无法核验，不重启、不重提，沿原恢复入口对账。
单独执行结果分析/生成方案只会返回实施请求，不拥有后继提交循环。

后台获取原任务终态后，核验产物和评价，再继续原研究主会话分析与实施，
由原独立评审会话质询。通过原检查且仍有预算才提交下一任务。
失败保留原编号和证据，不计作零分或有效结果；未知请求先对账。
工作台读取同一接受记录，并按项目的指标名称、方向和数值范围展示。

接入接口可复用不等于所有训练平台已实测。交付应逐项报告：原组件路径的兼容检查、
新项目/评价的实际远端任务、命令驱动的真实执行范围，以及尚未部署的外部平台。
接口存在、软件检查通过、平台成功、结果有效、目标达到和科学支持分别报告。

## 项目命令驱动的最小操作契约

以下供维护接入代码的同事使用，由Codex根据当前项目已有接口整理，日常用户不必填写。
管理器配置使用`schema=sdm-project-manager/v1`，明确`provider`、`namespace`、`owner`、
原Guard的`state_root`和`submission_registry`。`platform_requirements`声明该平台需要的
已安装能力；LPAI仍走其官方接入，不能改个平台名字绕开官方能力要求。

`execution_adapter`声明`version=1`、执行位置`remote`、固定驱动文件的绝对路径和摘要，
以及下表五个操作各自的命令参数数组。命令从标准输入接收一个JSON对象，标准输出只
返回一个JSON对象；不通过拼接shell传参。每次调用前核对驱动文件字节。

| 操作 | 输入 | 必须返回的事实 |
| --- | --- | --- |
| `probe` | `{request: 原请求}` | `namespace`、`owner`、`resource_uid`、`configuration`。配置必须反映实际资源与环境的稳定绑定；不要加入每次都变化的观察时间。原提交事务会在写入前再次探测并比较。 |
| `submit` | `{request: 原请求, plan: 原计划本地路径}` | 真实新任务的`uid`。只能提交该原请求；审批中明确返回审批状态，丢失响应时不得自行重提。 |
| `lookup` | `{request: 原请求}` | `{candidates: [匹配原请求的任务编号]}`。只读；限定原namespace、owner、请求键和执行资源，多个候选必须交给原管理器阻断处理。 |
| `read` | `{uid: 原任务编号}` | 同一`uid`、`namespace`、`owner`、`resource_uid`、`cluster`、`request_key`、`payload_digest`、标准化`status`；保留平台真实编号和终态。 |
| `collect` | `{uid: 原任务编号, request: 原请求}` | 成功时`{uid, lines: [原任务输出的SDM_JSON行]}`；失败时`{uid, logs: [实际日志文本]}`。不能由驱动编造分数或成功产物。 |

请求形态沿用原提交管理器：`action=task.submit`、唯一`request_key`、`name`、执行资源
`uid`、`cluster`和`data`。新项目的`data.command`是已审议且固定摘要的远端载荷，
由任务系统按原资源运行。`payload_digest`必须与核心`external_operations.sha(data)`
一致，不能使用不同的JSON编码规则代替。配置变化、身份不符或结果未知均保留原请求。

成功载荷输出结果、预测、固定划分、检查点和功能检查五项产物；驱动负责原样回收，
共同事件源负责摘要核验、指标重算和持久交接。不要在驱动里增加方案生成、科学审批、
自动改代码或另一个训练循环。`engineering_provider.py`示例只验证非模型的本地CPU
任务与原Guard对账，不能代替上述远端训练驱动或训练结果接受。

大数据项目可固定一份数据清单及其身份，数据本体保留在已授权的远端只读位置。
项目功能检查必须核对实际读入数据与声明清单/划分的关系；仅有路径存在或清单文件
摘要，不证明全部远端数据已核验。当前载荷为有界UTF-8源码与配置，不能直接携带
大型数据、二进制依赖或模型权重。

### 持续迭代状态与部署核验

启动返回的 controller_running 仅表示原后台及研究线程已核验；
automatic_iteration_active 还要求当前流程未阻塞。started-blocked 和
already-running-blocked 均保留同一个控制器，须报告具体原因及下一步，不能重复启动。
progress 中的阶段、执行方和结果交接状态来自原记录，不赋予执行许可。
普通分析与评审在原持续授权内自动接续；缺证据、未知调用和停止条件仍受原门禁约束。

项目检查同时返回实际入口版本、安装包摘要及已有研究启动文件的对照。
original-frozen-runtime 表示旧研究使用原冻结，不表示已经升级或可以重提任务。
启动文件不匹配或不可核验时，先核对原身份；不得直接覆写旧冻结。
